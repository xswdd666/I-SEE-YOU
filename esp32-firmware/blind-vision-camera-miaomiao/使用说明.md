# 喵喵同学语音唤醒固件

原版 `../blind-vision-camera/` 未修改。本目录基于原版增加通电后离线语音唤醒。

## 启动流程

1. 通电/按 R 复位后，外接 D0 蓝灯灭，D8 马达保持 LOW。
2. Sense 麦克风 GPIO42 时钟、GPIO41 数据，以 16 kHz 单声道监听“喵喵同学”。这时没有蓝牙广播、没有 Wi-Fi 连接，也没有初始化摄像头。
3. 检测到唤醒词后，释放唤醒模型与麦克风资源，D0 蓝灯常亮，初始化摄像头并广播 `BV-CAMERA-xxxx`。
4. 使用原来的摄像头 App 扫描、蓝牙连接和配网；有保存的 Wi-Fi 时自动重连。
5. 原 BLE UUID、配网分包、加密访问、设备 token、HTTP 启停及 MJPEG 接口保留。不是之前单独的“穿戴硬件·蓝牙测试”服务。

这是通电监听状态，不是断电或深度睡眠，仍持续耗电。再次监听需要按 R 重启，没有新增语音关机、按钮关机或手机马达接口。D5 仍为上拉输入。唤醒不自动开始视频推流，仍由 App 调用原来的启动接口。

## 手机开机/待机控灯

新版 App 在语音配网首页及硬件调试页均提供“设备开机（亮灯）”“设备待机（灭灯）”。首次上电仍须先说“喵喵同学”才能连接蓝牙。调试页先扫描选择设备；语音首页未选择时会扫描选择信号最强的兼容设备。

这两个按钮仅控制 D0 LED，不断开 Wi-Fi/蓝牙，不停止摄像头，也不进入深度睡眠；待机灭灯后仍能点击开机亮灯。App 读取设备反馈确认状态，未收到确认会显示错误。

协议沿用加密写 COMMAND_UUID `62f10004-7a2e-4b79-9c81-a64e5532b001`，10 字节原配网分包头，UTF-8 命令 `led_on` / `led_off`。配网窗口关闭后仍接受这两个命令，原 `commit` 仍受配网窗口限制。NETWORK_UUID 读取 JSON 新增布尔字段 `ledOn`，App 校验与请求一致后显示成功。其余配网字段不变。

APK：`../../交付文件/空间记忆助手-喵喵唤醒控灯.apk`。已通过 adb 覆盖安装，保留应用数据。

## 构建与烧录

Arduino ESP32 core 3.3.12；板型 XIAO_ESP32S3；PSRAM OPI；USB CDC On Boot Enabled，USB Mode Hardware CDC/JTAG。

CLI FQBN：`esp32:esp32:XIAO_ESP32S3:CDCOnBoot=default,USBMode=hwcdc,PSRAM=opi`。本地 core 的 `CDCOnBoot=default` 才是启用。

目录内的 `partitions.csv` 必须参与编译；Flash 8 MB，app0 从 0x10000 开始，model 分区从 0x510000 开始。无 OTA 双分区。编译出的普通 merged.bin 不包含模型，也会覆盖 NVS，不要直接用它烧录。

先运行 `python verify_package.py` 检查模型包。使用 esptool 分地址写入：bootloader 0x0、partitions.bin 0x8000、boot_app0.bin 0xe000、应用 .ino.bin 0x10000、wake-model/srmodels.bin 0x510000。不使用 erase-flash，不覆盖 0x9000–0xdfff 的 NVS。

烧录输出：`D:/codex-build/blind-vision-camera-miaomiao/`。烧录日志：`D:/codex-build/miaomiao-flash.log`。

本目录 `build/` 另存了已烧录的程序、分区表和引导文件，`SHA256SUMS.txt` 记录校验值。恢复此版本时在本目录执行（COM3 按实际串口调整）：

```powershell
& 'D:\ArduinoData\packages\esp32\tools\esptool_py\5.3.1\esptool.exe' --chip esp32s3 --port COM3 --baud 460800 --after hard-reset write-flash --flash-size 8MB 0x0 build/blind-vision-camera-miaomiao.ino.bootloader.bin 0x8000 build/blind-vision-camera-miaomiao.ino.partitions.bin 0xe000 build/boot_app0.bin 0x10000 build/blind-vision-camera-miaomiao.ino.bin 0x510000 wake-model/srmodels.bin
```

## 验证

115200 波特串口应出现 `WAKE_READY`，每 5 秒 `WAKE_LISTEN`。对麦克风自然说“喵喵同学”，应出现 `WAKE_DETECTED`、`DEVICE_AWAKE`，蓝灯亮；摄像头正常时出现 `CAMERA_INIT_OK`，手机能扫描到原服务。失败时不绕过唤醒自动启动蓝牙。

摄像头初始化失败仍可扫描蓝牙和配网，但不会开启 HTTP 服务器，需检查 Sense 扩展板/摄像头连接。

原固件的“开机按住板载 BOOT 清除 Wi-Fi”保留在唤醒后的初始化流程里。不要在唤醒时按 BOOT，除非要清除保存的网络。

备份位于 `../烧录备份/`：NVS 已独立备份；完整 Flash 的 stub 读取在 0x90000 出错，带 INCOMPLETE 的文件不完整，不能用于整机恢复。旧源码完整保留，可重新编译回退。
